NGX Storage

Helm charts for NGX Storage

Install the NFS, Fibre Channel or iSCSI CSI driver on Kubernetes or OpenShift. This guide uses chart version 26.1.1.

1. Add the chart repository

helm repo add ngxstorage https://ngxstorage.github.io/helm
helm repo update ngxstorage
helm search repo ngxstorage

2. Prepare your cluster

Choose a protocol the workers can reach. FC needs fabric zoning and multipath. iSCSI needs initiators and portal access. NFS needs access to the data IP and a worker mount helper. The default charts also expect the snapshot CRDs and controller on the cluster.

For FC, the fc-target-names file holds a comma-separated array of pre-created target names (for example target-a,target-b), not WWPNs.

Set secret_dir below to a private directory with a file for each Secret key. Files contain the field value with no trailing newline. storage-ips contains comma-separated management addresses. Choose the platform and protocol values before running the commands. This example creates a new namespace and Secret.

protocol=nfs                         # nfs, fc or iscsi
platform=kubernetes                  # kubernetes or openshift
extra_key=data-ip                     # select the key from the table
secret_dir=/path/to/private/secret-files
namespace="ngxstorage-${protocol}"
release="${protocol}-csi-ngxstorage"

kubectl config current-context
kubectl create namespace "$namespace"
kubectl -n "$namespace" create secret generic "${release}-config" \
  --from-file=storage-ips="$secret_dir/storage-ips" \
  --from-file=pool-name="$secret_dir/pool-name" \
  --from-file=api-key="$secret_dir/api-key" \
  --from-file="$extra_key=$secret_dir/$extra_key"

3. Install and check the driver

helm upgrade --install "$release" "ngxstorage/${release}-${platform}" \
  --namespace "$namespace" --version 26.1.1 \
  --set-string "secret.name=${release}-config" --wait --timeout 5m

kubectl -n "$namespace" get pods -o wide
kubectl get csidriver "${protocol}.csi.ngxstorage.com"

After the driver pods are ready, create a test claim using the installed StorageClass. Mount the claim in a pod and verify that a file written to the volume can be read back.
